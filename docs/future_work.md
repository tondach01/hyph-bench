# Deferred work

Concrete items that are known, evidence-backed, and deliberately not done. Each entry records what the issue is, why it was deferred, and what fixing it would involve.

The paper's Conclusion and Limitations sections carry the research-level framing. This file is the engineering ledger: it exists so that a later maintainer does not rediscover these items, and does not "fix" one of them in a way that silently invalidates published numbers.

The hard constraint behind most of the deferrals: every character in a word list is declared in that dataset's PATGEN `.tra` alphabet, and every entry participates in training. Changing the data changes the trie, so any data fix invalidates comparability with the reported runs. Data fixes therefore belong in a **new dated artifact directory** with a rerun of the affected datasets, never in place under `results/gpopt260828/`.

## Data quality

- **Turkish casefolding defect in `tr/wiktionary`** (affects 0.72% of entries). Naive lowercasing maps `İ` to `i` followed by U+0307 (combining dot above) instead of `i`. All 106 affected word forms also occur correctly spelled, so the list contains 106 double-spelled duplicates, and U+0307 becomes a spurious character in the Turkish PATGEN alphabet. Example: `i̇b-ra-him` alongside `ib-ra-him`. Fix: Turkish-aware casefolding in `scripts/process_dump.py`, then regenerate and rerun `tr/wiktionary`.
- **Wiktionary lemma artifacts** (at most 0.02% of entries per dataset). Chemical subscripts, place-name qualifiers that leaked in as standalone entries, and bare symbols: `de/wiktionary` 162 entries (`₂ & / ( ) + @ … ! ?`, e.g. `(saa-le)`, `(west)`), `nl/wiktionary` 83 (`€ = +`, e.g. `+-kaart`), `pl` 4, `cs` 2, `es` 1 (`nr̃o`). Fix: a filtering pass in the dump-processing step.
- **Not defects, deliberately kept.** The five curated lists (`cssk/cshyphen`, `cs/cshyphen_cstenten`, `cs/cshyphen_ujc`, `de/wortliste`, `is/hyphenation-is`) contain no non-letter characters at all. The 16 nonspacing marks in `th/orchid` are Thai vowel signs and tone marks (U+0E00–U+0E7F), a legitimate part of the script. Apostrophes are orthographically real and are kept: `nl` 5,735 entries, `tr` 880, `uk` 187, `it` 71, `pt` 6, `ru` 6.

## Reproducibility and tooling

- **The dataset overview table is not generated by any script.** `tab:sizes-statistics` in the paper was assembled by hand from the disambiguated word lists, with `Size` in KiB (`scripts/hyperparameters/stats.py::convert_kilobytes` divides by 1024). Three of seventeen rows had drifted from the current data and were corrected on 2026-09-01; `Avg line length` and `AHyphs` reproduce exactly for all seventeen. The `#Chars` column's exact definition is no longer recoverable from code: empirically it equals the `.tra` line count minus two, which reproduces fourteen of seventeen rows, but `cs/wiktionary` disagrees while its file is byte-identical, so the formula is not quite the original definition. Fix: a script that emits the whole table from tracked inputs, pinning every column definition in code.
- **The overview table describes files that are not tracked.** For non-Wiktionary datasets the `_dis.wlh` disambiguated lists are gitignored byproducts, regenerated by `make disambiguate_all`. `cssk/cshyphen` has no `_dis.wlh` at all; its row required disambiguating the expanded list. Fix: derive dataset statistics from tracked inputs, or track the disambiguated lists.
- **Figures are regenerated ad hoc.** The statistics quoted in figure captions are archived (`results/gp_suggestion_figures/stats.json`, `results/hero_suggestion_figures/stats.json`), but the figures themselves are produced by invoking `scripts/make_*_figures.py` by hand. Fix: a make target with pinned inputs and output paths.

## Experiments

- **Wider threshold bound.** Three selected profiles sit at the upper bound of the `[1,42]` threshold range (`cssk/cshyphen`, `is/hyphenation-is`, `ru/wiktionary`), which the paper's Limitations names. A `[1,64]` control run on one of those datasets would show whether the bound is binding. A draft claim about such a run was removed from the camera-ready because no artifact backed it; the run itself is cheap (roughly one hour for one dataset).
- **Repeated seeds.** Everything reported uses seed 42. The budget-matched Random/TPE comparison is a comparison of search methods, not an uncertainty estimate for the final search. A multi-seed repetition of the per-level search on a few datasets is the honest robustness check.
- **Superseded comparison evidence.** `results/hpo_baselines_8d/` holds Random/TPE runs made with the earlier line-index split; they are superseded by `results/hpo_baselines_grouped/`, which uses the same grouped surface-form-disjoint split as the final search. `results/hpo_representative_150/` holds the older restricted four-parameter comparison. Both are retained as history; decide after camera-ready whether to prune them.

## Research directions

These follow the paper's Conclusion and are recorded here with the code seams they would touch.

- **Beyond hyphenation.** The same formulation applies to other pattern-based segmentation tasks: textual, token, compound-word, and ligature-suppression patterns. The repository name `pat-gen-opt` was chosen to accommodate this, but the current objective and evaluator are hyphenation-specific ($F_{1/7}$ plus a trie penalty, hyphens as the unit of truth). Generalizing means a pluggable objective and a task-agnostic evaluator alongside the existing one.
- **Richer search and faster convergence.** Wider or differently shaped parameter ranges, more levels, and annealing-style schedules. The seams are the search space in `scripts/per_level_search.py` (weight labels, threshold bounds, pattern ranges) and the objective assembly in the same module.
- **Word list development.** Extending lists by bootstrapping and transfer learning, which would also address the data-consistency limitation the paper names.
- **Big alphabets.** Universal hyphenation and multilingual word segmentation need a Unicode-capable PATGEN (UTFpatgen). The current pipeline assumes the classical byte-oriented `patgen` with a per-dataset `.tra` alphabet, so this is a change of engine, not only of parameters.
